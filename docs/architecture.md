# Архітектура AI-агента

## Які проблеми вирішує агент

Агент автоматизує типові кроки лабораторної роботи: підготовку структури
кросплатформного Python-проєкту «Hello, World!», створення та запуск перевірок
`pytest`, а також підготовку GitHub Actions. Команди розділяють роботу на
окремі етапи, а skills містять спеціалізовані настанови для цих етапів.

Оркестратор виконує роботу послідовно. У разі помилки він зупиняється на
першій помилці, не приховує її та надає підсумковий звіт про виконану роботу
і результат.

## Skills

- `project-scaffold` — настанови зі створення структури проєкту.
- `build-and-test` — настанови зі збирання та перевірки проєкту.
- `github-actions` — настанови з автоматизації перевірок через GitHub Actions.

## Commands

Команди доступні як prompt-файли:

- `/git-init` — підготовка Git-репозиторію.
- `/create-project` — створення структури проєкту.
- `/create-build` — підготовка збирання та перевірок.
- `/create-actions` — підготовка GitHub Actions.
- `/check` — перевірка результату.
- `/lab1-init` — запуск початкового сценарію роботи агента.

## Дані між етапами

На початку агент отримує запит користувача та контекст відкритого
репозиторію. Кожен наступний етап використовує цей контекст і результати
попередніх команд, зокрема створені або змінені файли та повідомлення про
результат перевірки. Таким чином, команда перевірки спирається на результат
створення проєкту й підготовки запуску, а підсумковий звіт відображає
результати виконаних етапів.

Якщо команда повертає помилку, оркестратор передає її без приховування,
припиняє наступні етапи та формує звіт із зазначенням помилки й статусу
виконання.

## Відповідність файлів і ролей

| Шлях | Роль |
|---|---|
| `.github/agents/build-engineer.agent.md` | Manifest агента: визначає агента та його робочу роль. |
| `.github/prompts/{git-init,create-project,create-build,create-actions,check,lab1-init}.prompt.md` | Commands: окремі інструкції для етапів роботи агента. |
| `.github/skills/{project-scaffold,build-and-test,github-actions}/SKILL.md` | Skills: спеціалізовані настанови, які агент застосовує під час виконання завдань. |
| `.github/workflows` | CI: конфігурація автоматичних перевірок у GitHub Actions. |

Назви у фігурних дужках позначають перелік файлів із відповідними назвами,
а не окремі файли з фігурними дужками в назві.
